# 09: user-input-system

## Description

Подготовить задачу на пользовательский ввод с использованием новой Input System и класса `InputSystem_Actions`.

Базовое передвижение уже есть, делаем вторую итерацию

Область второй итерации:
- движение;
- стрельба.

Требования по движению:
- использовать `InputSystem_Actions` как источник инпута;
- поддержать движение по 8 направлениям;
- перед стартом движения добавить небольшой `input delay` для уточнения направления
  (в том числе для комфортного выбора диагонали);
- при удержании направления игрок продолжает двигаться без отрыва пальца от инпута;
- при отпускании и следующем явном нажатии команда движения попадает в буфер на `X` времени;
- окно буфера движения (`X`) и величина `input delay` должны быть настраиваемыми параметрами.

Требования по стрельбе:
- стрельба также читает команды из `InputSystem_Actions`;
- для стрельбы нужен буфер ввода на `X` времени;
- для стрельбы `input delay` не используется.

Дополнительные требования:
- ввод отделен от игровой логики (input layer -> systems);
- поведение буфера и задержки должно быть детерминированным относительно тиков/времени игры.

Интеграции:
- с `grid-movement`: передача нормализованных команд движения;
- с боевой системой (будущая задача): передача команд стрельбы;
- с `game-configs`: чтение параметров `movement input delay` и `input buffer window`.

Ожидаемый результат:
- `PlayerInputSystem` поверх `InputSystem_Actions`;
- `InputBufferSystem` (или эквивалент) для движения и стрельбы;
- разделение каналов ввода движения и стрельбы;
- базовые проверки сценариев: удержание, отпускание/повторное нажатие, диагональный ввод.
